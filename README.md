# JS SEO Audit

Пакет на Python для перевірки JavaScript SEO за списком URL. Для кожної адреси Chromium відкриває сторінку в чистому контексті. Пакет зберігає SEO-сигнали з початкової HTTP-відповіді та з DOM після виконання JavaScript. Сторінку відкриває звичайний Chromium без кліків і прокручування.

## Запуск у PowerShell

Потрібні Python 3.10+ і uv. Розпакуй ZIP, відкрий папку `js-seo-audit` у VS Code й виконай у терміналі наведені команди. Якщо Chromium уже встановлено для Playwright, переходь до другої команди.

```powershell
uv run playwright install chromium
uv run js-seo-audit https://your_site.com/ --output audit.json
```

Для кількох сайтів створи `urls.txt` у UTF-8 поруч із `pyproject.toml`. Додай по одній адресі на рядок. Домен без схеми відкривається через HTTPS. Для оцінки сайту додай головну й кілька URL різних шаблонів.

```powershell
uv run js-seo-audit --input .\urls.txt --output .\audit.json
```

## Параметри команди

```powershell
uv run js-seo-audit --help
```

| Параметр | Як працює |
|---|---|
| `URL [URL ...]` | Одна або кілька адрес прямо в команді. Їх можна поєднати з `--input`. |
| `--input .\urls.txt` | Читає адреси з UTF-8 файлу. По одній URL на рядок. |
| `--output .\audit.json` | Задає шлях до JSON. Типове значення — `audit.json` у поточній папці. Excel і спільний TXT записуються поруч. |
| `--wait-ms 3000` | Задає очікування перед знімком DOM. Типове значення — 2000 мс. |
| `--timeout-ms 30000` | Максимальний час очікування навігації до `DOMContentLoaded`. Типове значення — 20000 мс. |
| `--chromium-path "C:\path\to\chrome.exe"` | Використовує вказаний виконуваний файл Chromium. За замовчуванням Playwright відкриває встановлений для нього Chromium. |
| `--resume` | Використовує збережені результати для того самого файлу звіту, URL і параметрів. |
| `--block 'Назва=CSS-селектор'` | Порівнює заданий блок у початковому HTML та DOM. Параметр можна повторювати. |
| `--retry-wait-ms 9000` | Задає очікування для другого заміру. Значення має бути більше за `--wait-ms`. За замовчуванням — 6000 мс або на 1000 мс більше за перше очікування, залежно від того, що більше. |
| `--no-retry` | Вимикає другий замір. Використовується окремо від `--retry-wait-ms`. |
| `-h`, `--help` | Показує довідку в терміналі. |

## Файли після запуску

- `audit.json` містить повні дані для кожної URL.
- `audit.xlsx` містить аркуш «Домени» з підсумками й аркуш «Деталі URL» з порівнянням HTML, а також аркуш «Перевірити в Google». Усі три аркуші мають фільтр за доменом.
- `invisible-domains.txt` містить по одному домену на рядок. Домен потрапляє до списку, якщо хоча б одна URL з HTTP 200 показала появу або втрату основного тексту чи вибраного блоку після JavaScript. Враховуються обидва заміри. Після кожного прогону пакет дописує тільки нові домени, зберігаючи попередні рядки. Якщо файл ще не існує, він може бути створений порожнім. Він позначає URL для перевірки рендерингу й не підтверджує відсутність домену в індексі Google.

Пакет групує адреси за доменом із вхідного URL і показує кінцеву адресу, якщо вона змінилася. Усі три файли записуються поруч із файлом, заданим через `--output`. При іншій назві JSON зміниться назва Excel-файлу, наприклад `check.xlsx`. Усі прогони з результатами в одній папці поповнюють спільний `invisible-domains.txt`. Якщо результати попередніх партій записані в окремі TXT із префіксами, перенеси потрібні домени до спільного файлу. Позначки в Excel стосуються поточного прогону.

## Прогрес, відновлення та повторний замір

Під час аудиту термінал показує номер URL, адресу й статус збереження. Кожна завершена URL зберігається в `audit.json.checkpoint.sqlite3` поруч зі звітом. Якщо зупинив аудит через Ctrl+C, повтори ту саму команду з `--resume`. Використай ті самі URL, порядок, параметри та шлях до звіту.

```powershell
uv run js-seo-audit --input .\urls.txt --output .\audit.json --resume
```

При старті без `--resume` пакет починає новий прогін для цієї назви звіту. Якщо всі URL уже збережені, запуск з `--resume` повторно формує звіти із збережених результатів. URL, перервана до завершення замірів, перевіряється знову.

Для HTTP 200 пакет повторює перевірку, коли основний текст або заданий блок з’явився, зник чи не був знайдений за умовами аудиту. За стандартного першого очікування 2 с другий замір використовує 6 с. Якщо перше очікування довше, друге за замовчуванням становить щонайменше на 1 с більше. `--retry-wait-ms 9000` задає конкретний час, `--no-retry` вимикає повторний замір. Повторний замір відкриває URL у новому контексті браузера, тому між замірами може змінитися і відповідь сайту.

## Перевірка конкретних блоків

Додай по одному прапорцю `--block` на блок. Запис має формат `Назва=CSS-селектор`. Приклад для сайтів із відповідною розміткою картки рецепта:

```powershell
uv run js-seo-audit --input .\recipes.txt --output .\recipes.json --block 'Інгредієнти=.wprm-recipe-ingredients-container' --block 'Інструкції=.wprm-recipe-instructions-container'
```

Селектори застосовуються до кожної URL в команді. Для сайтів з різними шаблонами зручно робити окремі списки. Порівнюються кількість збігів, текст та його уривок у початковому HTML і DOM. Збіг селектора означає присутність елемента в DOM, зокрема коли його візуально приховує CSS.

## Аркуш «Перевірити в Google»

Аркуш містить точну URL, причину відбору, фразу з заміру за наявності, CSS-селектор і час очікування. Відкрий [Rich Results Test](https://search.google.com/test/rich-results), встав точну URL і після запуску тесту вибери **«Переглянути протестовану сторінку → HTML»** і пошукай фразу. Якщо фраза порожня, переглянь потрібний селектор або навігацію вручну. У колонці «Результат ручної перевірки» можна записати, що знайшов тест Google. Записи в цій колонці зберігай в окремій копії Excel, якщо плануєш повторно формувати звіт з тією самою назвою.

## Як читати audit.json

| Поле або код | Що перевірити |
|---|---|
| `raw` і `rendered` | Title, description, H1, canonical, robots, довжину й початок основного тексту, посилання та типи JSON-LD. |
| `main_text_added_after_js` | Більшість основного тексту з’явилася після JavaScript. Це залежність від рендерингу. |
| `main_text_lost_after_js` | Основний текст значно скоротився після виконання JavaScript. Перевір помилки та порівняй уривки тексту. |
| `html_changed` | Змінився певний SEO-сигнал. У записі є значення до та після. |
| `noindex` | Знайдено директиву в початковому HTML, DOM або HTTP-заголовку. Звіт указує, для якого бота. |
| `links_added_after_js`, `links_lost_after_js`, `hash_routes` | Перевір, чи виявить краулер посилання на потрібні посадкові сторінки. |
| `browser_resource_or_script_errors` | Chromium зафіксував помилку JS або проблему з ресурсом. Для оцінки впливу звір її з відсутнім контентом. |
| `url_changed_after_navigation` | Адреса браузера змінилася після отримання HTML, наприклад через JavaScript-навігацію. Порівняння HTML пропущено. |
| `http_status`, `inspection_failed` | Перевір код відповіді або причину, чому локальна перевірка не завершилася. |

Основний текст вибирається евристично з `main`, `article` або `body`. Порівняння вимірює текст у DOM, включно з текстом, який може бути прихований стилями. Попередження про зміну довжини спрацьовує за різниці щонайменше 100 символів, коли коротша версія має до 30% довжини довшої. Для перевірки конкретного блоку дивись уривки або відкрий HTML у Rich Results Test.

Пакет обробляє поданий список послідовно. Звіт описує спостереження Chromium. Для підтвердження того, що отримує Google, перевір підозрілі URL у Rich Results Test або в Search Console. Індексування перевіряється окремо через інструмент перевірки URL. Автоматичний пошук URL у sitemap і перевірка правил robots.txt залишаються наступними кроками розробки.

## Модулі

- `browser.py` отримує HTTP-відповідь і DOM, збирає помилки JS і ресурсів.
- `html.py` витягує сигнали з обох версій HTML.
- `compare.py` порівнює результати та формує знахідки.
- `cli.py` читає URL і запускає аудит.
- `reports.py` формує JSON, Excel і список доменів.
- `checkpoint.py` зберігає завершені перевірки для відновлення.
- `blocks.py` перевіряє CSS-селектори, `retry.py` визначає умови повторного заміру, а `google_review.py` добирає фрази для ручної перевірки.

Після встановлення Chromium перевірки можна запустити через `uv run python -m unittest discover -s tests -v`.
